# Expository Transfer · Android developer preview

**Full installed SFTP Save As acceptance (2026-11-05):** [Merged #545](https://github.com/gamesbyian/Expository/pull/545) passed the actual API35 [production Compose→OS CREATE_DOCUMENT→byte-verified SFTP Copy E2 #42171467518](https://github.com/gamesbyian/Expository/actions/runs/42171467518), **1/1 executed, zero skipped** on the exact head. A disposable pinned SSH server supplied the bytes; both the original source and the app-private verified journal were checked. This is a full installed synthetic-provider journey, not independent third-party/physical E4 or signed beta.

**FTPS protocol qualification (2026-11-05):** The opt-in [localhost-only lab #42171058668](https://github.com/gamesbyian/Expository/actions/runs/42171058668) passed TLS certificate rejection, encrypted normal directory listing/RETR, and authenticated MLST/RETR when a second read-only server deliberately refuses both MLSD and LIST. This supports the direct-file option without contacting a public service. The real Rebex interoperability concern [#54](https://github.com/gamesbyian/Expository/issues/54), full Android FTPS→SAF payload delivery, independent physical/third-party providers and signed beta remain unverified.

**Latest developer-preview improvements (2026-11-05):** Single local, pinned-SFTP and TLS-verified FTPS Save As now all require the OS picker result's actual WRITE permission ([#538](https://github.com/gamesbyian/Expository/pull/538), [#539](https://github.com/gamesbyian/Expository/pull/539)); both remote protocols provide session-only, exact absolute file-path Save As with independent authoritative file metadata checks ([SFTP #542](https://github.com/gamesbyian/Expository/pull/542), [FTPS #534](https://github.com/gamesbyian/Expository/pull/534)), and SFTP also pins the chosen file revision while Android's picker is open ([#540](https://github.com/gamesbyian/Expository/pull/540)). Recovery references can be inspected across multiple bounded 32-record windows ([#543](https://github.com/gamesbyian/Expository/pull/543)), without authorizing any restart/retry, cleanup or deletion. These are developer-preview routes, not claims of third-party interoperability or signed-beta readiness.

Expository Transfer is the **native Android** app in this repository's `android-transfer/` directory. The repository's GitHub Pages app is a separate **read-only** repository explorer. Native Transfer currently has real scoped Android file operations and authenticated SFTP/FTPS foundations, but **is not a signed beta or a complete FTP file manager**.

## What is working now

- **Single view (default):** its own navigable Android Storage Access Framework (SAF) folder browser, system Open/Create pickers for reviewed file Copy, local Open and Android Sharesheet, and separate authenticated SFTP/FTPS browser cards.
- **Optional Dual view:** independently configured Local/Local, Local/Remote and Remote/Remote panes, A/B swap, active-pane tabs on phones, preserved authenticated remote sessions and a near-top **Choose Pane A/B folder** shortcut. Select 1–12 files in either Local pane for reviewed, sequential, independently journaled **Local → Local Copy** into the opposite picked directory. The first ambiguity stops the batch, and no source is silently moved or deleted.
- **SFTP:** Apache MINA is bootstrapped with app-private Android user-home/working-directory resolvers before connections; real two-session Android emulator loopback byte relay passed [#202 E2](https://github.com/gamesbyian/Expository/actions/runs/40604003394). This does not prove physical-device or third-party server behavior. SSH host-key SHA-256 pinning, browsable 200→2000 listings, foreground Save As, **bounded 1–12-file local→SFTP uploads** with frozen source/destination plan [#463](https://github.com/gamesbyian/Expository/pull/463) and shared claimed Copy authority [#464](https://github.com/gamesbyian/Expository/pull/464) ([API35 real disposable pinned-SFTP bytes 5/5](https://github.com/gamesbyian/Expository/actions/runs/41899303840), not full UI E2), **inbound Android Shares requiring an explicit two-stage review and confirmation with changed-share invalidation** ([#465](https://github.com/gamesbyian/Expository/pull/465), no full UI E2), reviewed 1–12-file SFTP→opposite Local folder Copy (per-file fresh preflight, journal and scoped byte readback; now using the common immutable one-shot command and verified-only receipt dispatcher via [#459](https://github.com/gamesbyian/Expository/pull/459) and [#460](https://github.com/gamesbyian/Expository/pull/460)), **single-file and 1–12-file SFTP→SFTP Copy between separately authenticated dual panes** (device-relayed, journaled, exclusive create, SHA-256 readback and the common claimed approval/verified-only ledger via [#461](https://github.com/gamesbyian/Expository/pull/461); [synthetic two-session Android API35 5/5](https://github.com/gamesbyian/Expository/actions/runs/41895968811), not a complete UI or physical E4 witness), guarded single-file on-server Move and New Folder. Source bytes are preserved for Copy; remote destination writes use no-overwrite semantics and durable attempt records.
- **FTPS and explicit insecure FTP:** explicit and implicit TLS-validated FTPS browsing/Save As, authoritative MLST metadata checks, progressive encrypted listings and protected data connections. A session-only **absolute file path → MLST → Android Save As** action works when a file is absent from the listing ([#534](https://github.com/gamesbyian/Expository/pull/534), synthetic API35 5/5); narrowly classified directory command refusals can leave an otherwise authenticated FTPS session available for that separate, manual MLST check ([#536](https://github.com/gamesbyian/Expository/pull/536), adapter E1 only), but TLS, timeout, permission and unknown failures disconnect. This does **not** prove live Rebex data-channel compatibility or end-to-end authenticated FTPS→Android payload E4. Separately consented **unencrypted FTP browsing is available read-only**; it has no plaintext upload, download or destructive execution, and there is no automatic downgrade from FTPS/SFTP.
- **New Folder (local):** in a chosen writable SAF folder, review the name and collision-free complete parent listing, then create a **new** direct-child directory with write-ahead journal and exact post-create metadata verification.
- **Whole-folder Single and Dual SAF Copy:** [#292](https://github.com/gamesbyian/Expository/pull/292) established genuine two-OS-picker Single folder Copy and [#399](https://github.com/gamesbyian/Expository/pull/399) accepted shared Single recursive Copy; [#401](https://github.com/gamesbyian/Expository/pull/401) added fully successful Dual recursive Copy with independent picker grants, three verified steps, exact 137,119-byte destination readback, unchanged source, visible refreshed target and clean Activity teardown. The root action is reachable without nested scrolling; all writes still require explicit review. This is a disposable Android test provider, not a live cloud or handset interoperability result.
- **Safety and preview tools:** app-private AtomicFile attempt journals, separately AES-GCM protected **read-only** recovery context with exact private-record picker binding (#440) and truthful attempt/ACK/UNCERTAIN stage descriptions (#441), cancellation/uncertain receipts, content readback, preview-only SFTP bulk renamer and immutable planner/replay-policy scenarios. [Merged #442](https://github.com/gamesbyian/Expository/pull/442) adds an optional authenticated SAF tree-root fingerprint for later fresh-picker comparison, preserving older encrypted V1 records ([API35 recovery/recursive Copy 24/24](https://github.com/gamesbyian/Expository/actions/runs/41785520927), [recovery UI 2/2](https://github.com/gamesbyian/Expository/actions/runs/41785523338)). [#444](https://github.com/gamesbyian/Expository/pull/444) additionally seals an actual post-create **direct-parent + child ID/name/kind** witness in a separate write-once encrypted sidecar for recursive and Dual SAF Copy ([API35 25/25 recovery/recursive](https://github.com/gamesbyian/Expository/actions/runs/41827001016), [2/2 recovery UI](https://github.com/gamesbyian/Expository/actions/runs/41827006714)). A match identifies provider-reported child identity only. A create can happen without returning an ID or recording any witness. [#447](https://github.com/gamesbyian/Expository/pull/447) and [#448](https://github.com/gamesbyian/Expository/pull/448) separately seal completed source-stream byte count/SHA256 (not a post-restart destination proof). [#450](https://github.com/gamesbyian/Expository/pull/450) now offers **manual, READ-only comparison of the current created file's bytes against that hash**, only after fresh direct-parent authorization and exact-child reobservation, capped at 64 MiB ([API35 **26/26** recovery/recursive](https://github.com/gamesbyian/Expository/actions/runs/41832331793), [UI **2/2**](https://github.com/gamesbyian/Expository/actions/runs/41832338107)). A matching digest does not change journal state, independently reauthenticate the source, prove cloud sync, or authorize retry or deletion. **No durable restart queue, automatic resolution or cleanup is shipped.** A pure JVM per-step journaled bulk-rename executor stops on uncertain replies and parent drift, but it is **not connected to a real SFTP/SAF rename adapter or Apply UI** until stable remote child identity and true atomic no-replace semantics are demonstrated.

The optional **Local/Remote app-session access gate** has only a pure policy foundation ([#155](https://github.com/gamesbyian/Expository/pull/155)). The native BiometricPrompt/device credential callback, UI privacy gate and consented saved-profile feature are **not yet implemented**. A separate on-device AndroidKeyStore AES-GCM record-storage primitive exists for future integration, without saved logins or biometric enforcement. Existing connection passwords stay in memory rather than being saved between launches. See [session authentication design](../docs/android-transfer/SESSION-AUTHENTICATION.md).

## Download an experimental APK

For a reproducible CI-built developer APK, open [the repository's GitHub Actions runs](https://github.com/gamesbyian/Expository/actions), locate the latest successful trusted-main build dispatched by the owner-authorized `/transfer-native apk` command, and download the `expository-ftp-developer-debug-apk` artifact. New builds contain `expository-ftp-developer-debug.apk` and `SHA256SUMS.txt`. GitHub retains this artifact for **five days**, so a newer owner-triggered `/transfer-native apk` run is necessary after expiry. This is debug-signed, not release-signed; it is not backed up and is not available as a permanent store listing.

When testing, use **test-owned Android folders and separately authorized disposable SFTP/FTPS accounts**. Do not enter sensitive credentials or edit important remote data in this developer preview. Local tree grants are transient; the app does not request `MANAGE_EXTERNAL_STORAGE` or a global filesystem grant. Granting a folder in Android Files is a distinct action from selecting a source file and confirming a mutation in Expository.

APK naming policy: distributable Android artifacts must include the literal `expository-ftp` in the **APK filename itself**, not just in the GitHub Actions artifact/ZIP title. Existing archived builds retain their historical names. The local Gradle output remains `app-debug.apk` until CI packages the distributable file.

## Build and verify

From `android-transfer/`, use JDK 17 and the **repository-pinned Gradle 8.13 wrapper** (`./gradlew` on macOS/Linux, `gradlew.bat` on Windows). The examples below show the Unix invocation; substitute `gradlew.bat` on Windows. CI may continue using its separately pinned Gradle 8.13 setup until the wrapper is qualified as a trusted build entrypoint.

The committed `gradle-wrapper.jar` is byte-for-byte the [official Gradle 8.13 wrapper JAR](https://gradle.org/release-checksums/) (SHA-256 `81a82aaea5abcc8ff68b3dfcb58b3c3c429378efd98e7433460610fecd7ae45f`), independently cross-checked against Gradle's published checksum. The distribution URL uses HTTPS and `distributionSha256Sum=20f1b1176237254a6fc204d8434196fa11a4cfb387567519c61556e8710aed78`. The regular no-dependency Node suite checks the committed JAR bytes and properties. [Merged #445](https://github.com/gamesbyian/Expository/pull/445) now proves the **real** pinned wrapper rejects a deliberately false ZIP SHA-256 against an isolated local synthetic ZIP ([GHA #41827973225](https://github.com/gamesbyian/Expository/actions/runs/41827973225)). [Merged #449](https://github.com/gamesbyian/Expository/pull/449) proves the genuine pinned Gradle 8.13 distribution downloads and launches in a fresh cache ([GHA #41830835879](https://github.com/gamesbyian/Expository/actions/runs/41830835879)); [merged #451](https://github.com/gamesbyian/Expository/pull/451) extends this to **actual clean JVM/Android dependency resolution, core E1 scenarios, app/test compilation and lint** ([GHA #41832731297](https://github.com/gamesbyian/Expository/actions/runs/41832731297)). [Merged #453](https://github.com/gamesbyian/Expository/pull/453) additionally [forced a second genuine offline project/test/lint rebuild](https://github.com/gamesbyian/Expository/actions/runs/41888286737) from the same isolated cache with `--offline --rerun-tasks --no-build-cache`. This is *same-snapshot cache reuse*, not offline bootstrap from an empty cache. These checks do **not** establish complete transitive lockfiles/checksum metadata, independently reproducible cache provenance or SBOM; see [issue #326](https://github.com/gamesbyian/Expository/issues/326).

```sh
./gradlew :core:planner:scenarios :core:planner:locationScenarios :core:planner:directoryScenarios :core:planner:moveScenarios :core:planner:workspaceScenarios :core:planner:sessionAccessScenarios :core:engine:scenarios :core:engine:journalScenarios :core:engine:journaledCopyScenarios :core:engine:renameScenarios :adapter:ftps:scenarios :adapter:sftp:scenarios :testing:fake-endpoints:scenarios --no-daemon

```

Android compilation additionally requires Android SDK platform 36, build tools 36.0.0 and Google Maven dependencies. Current baseline: AGP 8.11.1, Kotlin 2.2.20, Compose BOM 2025.12.00, minimum Android API 26, target 36. Don't infer target-37 Android 17 LAN permission acceptance from target 36.

**CI routes:** the changed-path JVM pipeline runs E1 scenarios on every native PR. Owner-authored `/transfer-native apk-pr` compiles an immutable same-repo PR head. `/transfer-native emulator-pr WorkspaceNavigationUiTest` runs the targeted Android UI suite; exact allowlisted method selectors support cost-conscious positive picker/provider tests. Owner `/transfer-native apk` on a PR comment builds `main`, publishes SHA256 and an expiring debug APK. See [agent guidance](AGENTS.md) and [CI workflows](../.github/workflows/transfer-native.yml) for authorization and provenance.

## Evidence and limitations

**Actually accepted on an Android 15/API 35 emulator:**

- A complete system Open→Create Document Copy with byte-for-byte source preservation and provider-readback proof, plus inbound Share race safety ([#103](https://github.com/gamesbyian/Expository/pull/103)).
- **Two independently real OS-picked SAF folder grants and a Local→Local document Copy**, with a verified journal receipt and preserved 131,099-byte source ([#151](https://github.com/gamesbyian/Expository/pull/151), [exact test run #40462489116](https://github.com/gamesbyian/Expository/actions/runs/40462489116), 1/1). The test uses disposable MediaStore Downloads fixtures, not fabricated picker grants.
- 20/20 Dual workspace and folder-picker shortcut UI assertions [#40458822027](https://github.com/gamesbyian/Expository/actions/runs/40458822027) and 19/19 separate New Folder UI/policy tests [#40457974299](https://github.com/gamesbyian/Expository/actions/runs/40457974299). **Real system-picked Android New Folder creation** later passed [1/1 #40583517342](https://github.com/gamesbyian/Expository/actions/runs/40583517342) on merged [#157](https://github.com/gamesbyian/Expository/pull/157), including exact provider child identity, durable verification journal and unchanged test-owned marker bytes.
- **Reviewed 1–12-file Local↔Local Copy**, with first-of-batch fresh source preflight, each operation journaled separately, actual streamed content SHA-256 provider readback and stop-on-uncertainty. Merged [#170](https://github.com/gamesbyian/Expository/pull/170) passed [1/1 positive API35 two-system-picked-tree, two-file run #40584985952](https://github.com/gamesbyian/Expository/actions/runs/40584985952) at exact source `878dc5bbe65c8e3beb4e196c4abb464c0bcb74d5`; 3–12-file and external provider E2/E4 remain untested.
- Local→SFTP batch review 14/14 UI assertions ([#139](https://github.com/gamesbyian/Expository/pull/139)) and SFTP→Local review 15/15 ([#140](https://github.com/gamesbyian/Expository/pull/140)) originally established only review behavior. Since then, [#205 E2](https://github.com/gamesbyian/Expository/actions/runs/40609736695) verified 131,109 real bytes from a test-owned Android MediaStore document into an authenticated localhost SFTP server; [#204 E2](https://github.com/gamesbyian/Expository/actions/runs/40609635841) passed 23/23 batch selection/guard regressions. Neither proves physical hardware or third-party SFTP interoperability.
- Synthetic localhost **SFTP host-key/collision** and **FTPS TLS/data-read** labs, separate from the Android UI/providing actual network from the handset.

**Still required:** real-device and third-party-provider acceptance for New Folder and multi-file SAF Copy, live authorized external-server SFTP and Android FTPS payload acceptance (localhost Android SFTP bytes passed #205), remote/cross-route recursive folder parity and third-party/cloud provider interoperability, remaining cross-pane Copy/Move directions and multi-file remote relay, executed/undo-safe bulk rename, durable transfer queue/recovery after app death, protected remembered credentials, actual Drive/Docs destination delivery, accessibility/responsiveness matrix, physical Android and independently signed beta. The exact evidence and gate state live in the [release ledger](../docs/android-transfer/RELEASE-READINESS.md); no release should bypass G0–G9.

The app and its Android Gradle root are intentionally relocatable; do not migrate or alter the public Pages explorer without separate approval.
