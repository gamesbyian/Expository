# Expository Transfer: native-agent operating instructions

Expository Transfer is the **Android-native file-transfer** app under `android-transfer/`. Root Pages `index.html` stays a **separate read-only GitHub browser**. The app is a developer preview, not beta-ready. This guide is a stable router, not a diary of completed PRs.

## Immutable safety rules

- Native credentials, server names, private filenames, OAuth/session tokens and user bytes never appear in source, public CI logs/artifacts, screenshots or shared web app. No shared web GitHub tokens. Explicit SFTP connection-only bookmarks (#234) use the AndroidKeyStore encrypted app-private one-shot record store. They contain host, port, folder, username and independently verified SSH pin, **not passwords**, private key credentials or automatic sessions. No biometric unlock, user-auth-bound vault key, saved-password profile or silent restore exists.
- Plain FTP is a separately consented **read-only browser** (#213); its password and metadata travel unencrypted. No automatic fallback from SFTP/FTPS and no plain FTP download/upload, destructive operation or secure-receipt claim. Enabling insecure browsing does not authorize a transfer.
- No `MANAGE_EXTERNAL_STORAGE`, guessed SAF filesystem paths, assumed persistent URI grants, trust-all certificates, ignored SFTP host key, automatic plaintext FTP fallback or hidden Google OAuth scope expansion. Android target currently 36; test Android 17 LAN `ACCESS_LOCAL_NETWORK` before upgrading target to 37.
- UI, picker, drag and accessibility actions produce the same immutable, reviewed operation plan. Revalidate right before mutation; journal before changes. Copy preserves originals. **Never optimize Copy into remote rename.** Same-server Move requires verified authority/capability; cross-authority Move needs verified Copy then separately approved source deletion.
- On ambiguous write/rename/commit/Drive create **stop and reconcile**, never auto-retry or delete unknown staged data. Receipts may claim `CONTENT_HASH_VERIFIED` only on real comparable content proof; Share/External Open are handoffs, not Drive/Docs saves.
- The required UX offers a **permanent full-featured single-location browser by default** and an **optional dual-location view** (Local/Local, Local/Remote, Remote/Remote); responsive A/B tabs in dual view are not the single-location mode. **Already implemented, still incomplete:** default Single has a separately scoped Local SAF browser and route-specific pinned SFTP, verified FTPS and separately opt-in insecure read-only FTP browser cards; optional Dual has independently selectable Local/Local, Local/Remote and Remote/Remote panes with live trusted SFTP/FTPS and explicit read-only FTP / anonymous public GitHub browse cards, A/B tab collapse, swap and two limited reviewed SFTP Copy directions. This is not full feature parity with a unified single-location browser, all six cross-endpoint Copy/Move routes, native drag support or physical-device acceptance. SFTP bulk rename currently previews only. Do not relabel those remaining gaps as delivered.

## APK artifact naming

All future downloadable Android Transfer APKs must include the exact token `expository-ftp` in the **`.apk` filename**, not merely the Actions artifact/ZIP name. The trusted-main developer workflow packages `expository-ftp-developer-debug.apk` in `expository-ftp-developer-debug-apk` and writes `SHA256SUMS.txt` against that published filename. Any PR-head, emulator, signed beta or release workflow that uploads a distributable APK must maintain this policy, preserving build variant/version labels where helpful. Historical artifacts need no retrofit.

## Implement, verify, integrate

- Prefer one shared source → destination request/preflight/approval/receipt boundary across Single, Dual and future drag, then incrementally extract UI-owned orchestration from large route cards. Never build a second independent engine per endpoint or perform an untested big-bang UI refactor. The dependency graph and exact route checklist live in [the execution plan](../docs/android-transfer/EXECUTION-DEPENDENCIES.md).
- Pick one independently testable vertical slice. Reuse pure Kotlin planner under `core/planner`, write-ahead attempt journal in `core/engine`, scoped Android SAF and trusted `adapter/sftp`/`adapter/ftps`. Source `android-transfer/` must remain relocatable to a native repo; do not mutate web explorer to ship transfer features.
- Default **cheap**: from `android-transfer/`, JDK 17 / Gradle 8.13, run `gradle :core:planner:scenarios :core:planner:locationScenarios :core:planner:directoryScenarios :core:planner:moveScenarios :core:engine:scenarios :core:engine:journalScenarios :core:engine:journaledCopyScenarios :adapter:ftps:scenarios :adapter:sftp:scenarios :testing:fake-endpoints:scenarios --no-daemon` as relevant; Android code also needs `gradle -PwithAndroid=true :app:assembleDebug --no-daemon` with SDK 36. Prefer only affected tasks locally; the full command is for broader regression.
- Opt-in workflows require review. Owner-authored PR comment `/transfer-native apk-pr` compiles immutable same-repo PR head; `/transfer-native emulator-pr <ClassName>` runs the allowlisted targeted API 35 suite, or omit class for full expensive suite. These **do not** use production server credentials. Trusted-main-only `/transfer-native ftps-lab`, `sftp-lab`, `apk`, and `emulator` serve controlled/provenance jobs. Consult workflow YAML/operations doc for exact authorization before running; no manual live mutations against public demos. One relevant scoped test is better than repeated broad retries.
- Treat **E1** pure/JVM, **E2** actual Android emulator (including disposable picker/providers), **E3** controlled protocol/approved external *read-only* compatibility, **E4** real authorized provider/physical device and **E5** independent signed beta as separate. Every acceptance note needs tested code SHA, workflow ID, test scope, inspected assertion/result, limitations. A successful APK build is compile evidence only. A `skipped` unrelated issue-comment workflow is not a failing test.
- For any blocked acceptance PR, require exact-head observed proof at the advertised E2/E3 gate; compile-only checks and a stale PR description do not authorize merge. Put current PR-specific blockers in the work queue, not this permanent agent router.
- Finish each PR: review concurrent changes, test exact head, merge only qualified changes, update ranked queue/ledger *without duplicating history*, link evidence, hand off next runnable step. Do not open routine planning-only PRs when a functional slice can be delivered.

**Do not claim:** physical Pixel, TalkBack, live Android SFTP transfer bytes, real Google Drive write, native Docs conversion, complete six-route cross-pane operations, executed remote bulk rename or process-death recovery without observed proof. A passing API35 UI class does not supply live authenticated network receipts.

## Future universal location scope

Read [universal locations](../docs/android-transfer/UNIVERSAL-LOCATIONS.md) before changing endpoint abstractions, provider pickers or cross-pane transfer planning. Approved future native adapters include scoped Android DocumentsProvider/Google Drive, separately authorized Drive API and GitHub repository trees; public GitHub repositories now have an anonymous read-only Single/Dual browser (#221), with synthetic API35 listing decoder proof; #226 adds a separately reviewed public GitHub original-file Save As for pinned SHA-1 blobs up to 4 MB into Android's new-document picker, with independent provider SHA-256 readback (synthetic GitHub E2 only). There is no native Google Drive location, authorized GitHub write/private repository access, or E4 physical/live-network proof. Default Single remains first-class, Dual chooses any two authorized locations. GitHub writes are reviewed branch/commit operations and must **never** leak into read-only root Pages app. Keep pending scope separate from the release evidence ledger.
