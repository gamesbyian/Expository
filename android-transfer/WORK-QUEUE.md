## Consolidated release-blocker ownership

The 45-item owner audit describes overlapping symptoms, not 45 independent implementation jobs. The [consolidation crosswalk](../docs/android-transfer/RELEASE-BLOCKER-CONSOLIDATION-2026-11-03.md) assigns one primary delivery workstream to every concern:

- **T1:** Shared command, consent and Single/Dual/button/keyboard/drag parity (W01/W02; #324/#28)
- **T2:** Durable per-item queue, interruption, reconciliation and truthful receipts reused by all operations (W05; #325)
- **T3:** Verified SAF/SFTP/FTPS adapter capabilities and full file/folder/Move routes (W03/W04/W07; #28/#54)
- **T4:** Rename Apply and N-folder Smart Merge, each using T1–T3 and its own specific collision/rollback tests (W06/W14; #26/#384)
- **T5:** Real original-to-Drive and distinct Docs conversion, followed by separately scoped new providers (W08; #27)
- **T6:** Session authentication, profile protection and reproducible dependency/build trust (W10/W13; #25/#326)
- **T7:** Shared physical-device, accessibility, measured-performance, security and signed-beta evidence (W11/W09; #327)

Implement narrow, verifiable user journeys across these foundations, not parallel UI-specific writers or duplicate journals. Independent capability probes may run alongside the shared executor. Do not close broad requirements on a passing sub-route, and do not collapse distinct E2/E3/E4/E5 proof.
