## Baseline already in main

- Native Kotlin/Compose app and developer-only debug APK workflow with required `expository-ftp` filename. [#193](https://github.com/gamesbyian/Expository/pull/193) hardens source-parent identity and SAF grant-scoped Move routing (E1); [#195](https://github.com/gamesbyian/Expository/pull/195) adds only a provider-neutral, 2,000-item paged folder model and GitHub mutation refusal (E1), not working cloud/repository panes. A successful build is **not** a signed beta.
- Default Single view: scoped Local tree browse, OS Open→Create Document Save As, New Folder, Open/Share; separate pinned SFTP and TLS-validated FTPS route cards. Optional Dual view: independent Local/Local, Local/Remote, Remote/Remote pane identities, A/B mobile collapse and swap; SFTP and FTPS live browse cards. **Single remote browser is not yet unified; most cross-pane routes are missing.**
- Guarded Local→Local Copy of 1–12 selected files: a disposable API35 emulator proved **two files** with two real picker grants, byte readback and preserved originals ([#170 E2](https://github.com/gamesbyian/Expository/actions/runs/40584985952)). Scoped New Folder mutation likewise passed real picker/provider E2 ([#157](https://github.com/gamesbyian/Expository/actions/runs/40583517342)). **Neither proves cloud/physical device.**
- Real API35 Android E2 SFTP→SFTP localhost TCP, independent pinned sessions, 131,113-byte relay/readback, preserved source and Android durable VERIFIED journal passed [#202](https://github.com/gamesbyian/Expository/actions/runs/40604003394); this is not a public/third-party SFTP server, actual two-pane UI-driven transfer, physical E4 or signed E5. Android MINA now initializes app-private user-home/working-directory hooks, preventing the earlier Android runtime startup error. Source-pane mutations and workspace swaps are disabled during a relay in [#201](https://github.com/gamesbyian/Expository/pull/201) ([E2 UI #40603797443](https://github.com/gamesbyian/Expository/actions/runs/40603797443)).
- Reviewed Local→pinned SFTP 1–12-file Copy ([#139](https://github.com/gamesbyian/Expository/pull/139)) and one SFTP→other-pane SAF file Copy ([#140](https://github.com/gamesbyian/Expository/pull/140)) have E2 UI/guards, **not live Android-to-SFTP payload proof**. **Merged [#200](https://github.com/gamesbyian/Expository/pull/200)** adds a one-file, separately authenticated SFTP→SFTP Copy journey with device relay, no-overwrite exclusive destination, attempt journal and SHA-256 readback: exact-head [E3 synthetic localhost two-session and cancellation lab #40602069145](https://github.com/gamesbyian/Expository/actions/runs/40602069145), [Android APK/test compile #40602075129](https://github.com/gamesbyian/Expository/actions/runs/40602075129). This is **not** live Android-to-server or physical-device E4. One-file pinned SFTP New Folder/Move and FTPS Save As also exist. SFTP/FTPS browse is progressively bounded at 2,000 rows, not unlimited.
- Durable per-copy attempts and per-step rename journals: [#185 E2](https://github.com/gamesbyian/Expository/actions/runs/40581701094). Pure journaled bulk-rename engine: [#175 E1](https://github.com/gamesbyian/Expository/actions/runs/40577721321), capability expiry [#190](https://github.com/gamesbyian/Expository/pull/190), 2,000-row complete SFTP preview [#177](https://github.com/gamesbyian/Expository/pull/177). **Remote Rename Apply remains disabled** until no-replace semantics/stable identity are established.
- [#182 AndroidKeyStore E2](https://github.com/gamesbyian/Expository/actions/runs/40581221648) added encrypted-at-rest, one-shot app-private record storage. **No login/profile-save UI, password restoration, biometric gate or session-lock enforcement.** [#191 E3](https://github.com/gamesbyian/Expository/actions/runs/40586114313) bounded SFTP directory enumeration at a synthetic pinned localhost server.

## Accepted proof, limits and handoff

**E1** pure Kotlin/JVM; **E2** real Android emulator and disposable scoped providers; **E3** controlled authenticated protocol lab; **E4** physical handset/authorized live destination; **E5** independent signed release. For every acceptance claim record exact SHA, test suite, run ID, assertion and its limits in the [release ledger](../docs/android-transfer/RELEASE-READINESS.md). Do not count skipped Actions jobs as failures or compile-only tests as transported bytes.

Use the least expensive relevant test: native JVM regression first, then exact-head Android compile or targeted API35 emulator test for changed Compose/provider behavior. User-authorized PR comment `/transfer-native apk-pr` or `/transfer-native emulator-pr <ClassName>` invokes the scoped expensive checks, where supported by the workflow. Live remote writes require an explicitly authorized disposable fixture. Never log credentials, real paths or file bytes.

For each slice: inspect current main/PRs/issues; make a focused code+test PR; run exact-head checks; merge only safe verified work; update **this queue only when a priority or delivery state changes**, and the release ledger only for observed evidence. Do not paste PR histories back into this file. **G0–G8 remain in progress and G9 not started** unless the release ledger explicitly advances them.
