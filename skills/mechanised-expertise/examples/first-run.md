# Skill entrypoint acceptance walkthrough

This is a routing demonstration, not evidence that any actual app behaves correctly.

## Case A: one-label typo (no new state)

Read the accepted label and its closest implementation. Confirm that the replacement is specified, reversible and affects no behavior. Select routine. Edit the label and run the existing targeted test. **Do not** generate an inquiry card, conduct a competitor survey, invoke Concept Model Engineering, or compile a chain of procedures. Receipt: changed file + executed check + remaining unknowns.

## Case B: compact transfer row in an app with several accounts

Read the current product goals and UI. Identify an actually present uncertainty: could a row's server identity become unrecognizable or mutable during a refresh while a user activates a control? Choose the user-needs route; inspect current constraints, user complaints, comparable controls and accessible focus. If the action targets an asynchronous remote server, open the boundary trace reference as a *concrete dependency*, never merely because the prompt contains "file". Generate a question only if different answers change the layout/behavior/test. Map `goal -> environment identity -> visible row -> action -> approved target -> feedback` only if an unlinked relation could change the result. Receipt: decision criterion, proposed option, reversal test, unexecuted runtime proof.

## Case C: purportedly missing relationship in a media concept map

Read the focus question, known graph and supporting sources. If the edge absence affects a proposed user journey, invoke Concept Model Engineering. Run reverse traversal, seek previously unextracted existing facts and alternate names, then search a held-out source and credible prior implementation. Mark as map repair if found. Label candidate frontier only if adequately qualified, never from a blank diagram alone. Receipt: graph delta, source coverage, falsifier and next bounded action.

## Case D: native Android implementation with settled requirements

Start in Android App Development, not all four skills. Inspect host AGENTS.md, shipping call path, tests and acceptance. Only invoke Mechanised Expertise if a specific consequential uncertainty survives those checks, and load its single targeted reference. Receipt: exact commit, actual test tier and shipped status.

## Agent walk-through pass condition

A reviewer reading only the main `SKILL.md` should identify the correct entry route for each case, load at most one reference initially, produce an action with an independently checkable stopping condition, and avoid converting unexecuted proposals into observed results. This file defines a smoke-test expectation, not a recorded agent trial.
