# Teaching case: a compact multi-environment transfer list

**Hypothetical example.** It is not a current app specification, user-research report or test receipt.

The visible request is to make each transfer occupy less space. A naive repair shrinks padding and typography. The expert cue is that row density affects recognition, access to frequent controls, the exact environment owning each transfer, status truth and accessible reachability.

**Inspect current behavior:** owner decisions, the actual list composable, sorting/identity, normal and compact viewport, 200% type, per-row actions, expansion/detail, asynchronous loading and what happens when a connection drops. Avoid asking the owner for code facts.

**Research need and prior art:** compare several actual client list interfaces for name/metadata ordering, default actions and hidden details; look for original-language comments describing “always-visible toggle”, “extra step”, “I can't find the menu”, and accessibility frustration. Preserve the difference between a screenshot, a developer claim, and observed user experience.

**Model if a cross-scope link remains uncertain:** `user goal -> transfer(environment, item identity) -> visible row -> selected control -> approved target -> server result -> user feedback and recovery`. The missing link to investigate is whether a row reordered by an incoming refresh can retarget a pending action. First inspect whether the source code already freezes exact identity; a blank diagram cannot establish a defect.

**Options:** A compact row with name, environment cue, progress, status and primary action plus quick expansion; B extremely dense text with overflow; C large cards. Compare task steps, discoverability, large-type space, one-handed reach and exact-target safety. Do not automatically add a review screen for ordinary safe operations.

**Potential reversal:** A loses if text scaling hides names or buttons; B loses if frequent actions become undiscoverable. A density option may be justified if distinct segments need different information hierarchies.

**Oracle:** installed screen at compact/expanded sizes, 200% font, TalkBack/keyboard focus and state announcements, meaningful non-color cues, exact-target operation while list reorders and live error/recovery states. A Compose preview or a passing mock isn't sufficient to prove the real remote effect.

**Retain only after observation:** the cue that exposed a consequential missing requirement; the questions that wasted time; evidence that the solution beat its alternatives; whether an apparent concept gap was already represented.
