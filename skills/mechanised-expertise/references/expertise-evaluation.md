# Expertise evaluation and proportional investigation

An instruction may be useful only under particular conditions. Each proposed expertise mechanism should explicitly record the following seven fields.

1. Source and scope: exact pinned original rule and applicability. Distinguish published source, translation, fork, and our inferred suggestion.
2. Trigger: an observable cue in code, user journey, platform behavior or affected data that activates the question.
3. Consequential inquiry: question, cheapest trustworthy answer source, and the alternative answer that would reverse the current plan.
4. Conceptual model: relevant entities, roles, states and missing directed edges; perform only if mapping relationships can change the decision. Absence in the map may be an acquisition omission, alias, schema blind spot, contradiction, version boundary, excluded requirement or qualified frontier candidate.
5. Choice: a preferred conventional option and its serious exception, without using numeric scores to override hard constraints.
6. Oracle: an actually observable positive and discriminating negative outcome, with tested shipping entrypoint, environment, source revision and remaining limitations.
7. Retention: outcome and unexpected counterexample, time and compute cost, unnecessary questions, and whether the conditional rule merits revision.

## Evidence standards

Code compilation is not real user-journey verification. Simulated/mocked tests, installed emulator evidence, physical device evidence, provider interoperability, user acceptance and controlled comparisons are different levels of proof. Do not claim success when tests have not run.

Repository prevalence, authorship independence, source authority and measured skill effectiveness are independent dimensions. Deduplicate copied rules and translations conservatively, leaving ambiguous similarity for review. Do not claim original engineering judgment simply because a popular skill has a directive.

## Matched trial design

Evaluate incomplete and unfamiliar mobile requests, plus small reversible negative controls. Compare skill and control under the same model, tools, context and budget using a withheld prompt and independent reviewer. Review how many consequential unknowns were found, what sources were searched, whether source citations entail the claimed recommendation, whether a conceptual gap is genuine, whether the decision respects user goals, and whether verification could catch a meaningful regression. Penalize irrelevant questions, unproductive abstraction and owner burden.

A fixed-option diagnostic or self-declared concept tags can be gamed and cannot measure reasoning quality. Independent review of generated questions, decisions and real implemented behavior is mandatory. Exclude exposed or contaminated trials. Report failures and experimental costs, not only wins.

Suggested scenario families: multi-environment reconnect, fresh torrent test fixtures, dense accessible transfer browsing, shared storage protection with approved user destinations, installed Room upgrades, a trivial typo negative control, cross-media metadata relations, and Android reboot/resume limitations.

This is methodology, not an execution report or proof of benefit. The larger experiment is distributed separately in the v0.8 corpus archive.
