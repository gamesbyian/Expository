# Platform playbooks: select the correct Android primitive

These are decision/acceptance patterns, **not** copy-paste API claims about every Android release. Validate current target SDK and provider with official Android documentation. Read only the applicable section.

## SAF, Photo Picker and public Downloads

- **READ**: a picked URI is an access capability scoped to actual flags and grants. Confirm `ContentResolver` operations and the selected provider; do not guess a filesystem path, persist transient Photo Picker access or obtain MANAGE_EXTERNAL_STORAGE merely for convenience.
- **Create new**: use documented provider create semantics; verify the provider actually returned a fresh object before writing. `openOutputStream(uri, "w")` may truncate or replace provider-specific content. If returned identity is an existing object, refuse a Create New operation.
- **Keep both**: choose a new independently verified object, not an unchecked generated name. **Replace** requires a separately reviewed exact existing target, explicit consent, new permissions and honest partial-write semantics.
- **Private immutable original**: stage, fsync/verify length + digest; reserve destination exclusively (e.g., CREATE_NEW if supported), reverify, then commit Room rows. Exclusive reservation does not guarantee atomic visibility of completed bytes. Journal crash windows and distinguish a proven crashed partial from a foreign or already registered file.
- **Torrent native payload**: selected-path regular file recheck/reuse may be normal intentional behavior. Do not generalize immutability rules from export/photo. Block traversal, symlink escapes and unintended unrelated writes.
- **Copy/Move/ZIP**: validate parent/child relationship, exact authority/grant, source and target freshness, sizes, archive-slip/duplication/expansion. Local-to-remote Move is verified Copy then separately confirmed source deletion, not a rename shortcut.

**WRONG:** `if (!target.exists()) temp.renameTo(target)` as no-overwrite publication.

**RIGHT:** platform-supported exclusive create, independent bytes validation, owned-crash recovery, and documented collision policy. The specifics depend on app-private POSIX, MediaStore or SAF.

## Room and image lifecycle

- Migration: test populated *actual historical* schemas through generated Room exports. Verify row counts, memberships, references, unknown pending jobs and hashes before/after; avoid destructive migration. SQLITE-only simulated data does not prove Room on device.
- Admission: the app must accept or explicitly defer a share/picker result before it clears the intent or temporary URI. Busy state must preserve visible retry/dismiss; process death may require repick.
- Worker and wallpaper: distinguish OS side-effect entry, acknowledgement and observed current state. If failure occurs after attempting a change, preserve a durable pending/uncertain token and halt automatic repeat.
- APK update: stable signer across builds matters. Use `adb install -r` with populated real Room and private bytes; never uninstall to bypass signer mismatch. A temporary same-run test signer only proves migration under a shared test signer, not owner certificate continuity.

## Background and networking

- Foreground service, JobScheduler and WorkManager constraints change by target/device/OS. Test actual lifecycle (screen off, app swiped/stop, Doze, process death, reboot, low storage, network change). Never promise guaranteed short-interval background work without Android-supported semantics and device evidence.
- For blocking reads/writes, cancellation is a request; recheck the owning attempt after every blocking boundary before further effects or success receipt. Preserve source after partial output.
- Freeze exact endpoint, principal, instance and object identity before suspension; reject public authenticated-looking RPC reads when credentials were supplied but never challenged. Timeout or 401 after a write creates uncertainty, not permission for blind retry.
- UI pending/offline/unknown state must correspond to durable command state, not a stale spinner or optimistic notification.

## Compose, accessibility, performance

- Keep Compose rendering side-effect-free; do not perform disk/network mutation during recomposition. One view state owner for every authoritative setting and command.
- Test smallest supported logical width and high font scale, landscape/IME/safe insets, 48dp targets if project policy, TalkBack semantics, keyboard focus, large server lists and reduced-motion. A visible enabled item clipped inside nested scroll is a production reachability defect.
- Profile real jank, frames, heap and bitmap allocations before refactoring, then compare same realistic fixture; bounded DB query tests do not establish smooth 12,000-image Home performance.
- Inspect actual screenshot pixels at exact viewport/scale; an atlas generated by CI is not automatically visually approved.

## Trustworthy packaging

- Separate debug compile, installed emulator journeys, external provider credentials, owner-accepted visual/tactile output, permanent signing, upgrade safety and publishable signed release. Report these independently.
- Keep secrets out of PR logs, fixtures, APKs and screenshots. Pin privileged CI actions and do not run attacker-controlled PR code with release permissions.
