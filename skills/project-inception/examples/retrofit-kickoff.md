# Illustrative Retrofit kickoff

This is a worked research template, not an authorized product specification or proof of any external tool's performance.

**Owner concept:** annotate mechanical-room photographs; identify replacement sites and equipment references; send image, selected catalog material and instructions via AYA to a preferred agent for conceptual renovation visualization.

**Recover:** repo state, owner choices, AYA actual adapter contract, data-sharing approval, current photo handling and source licensing. Do not assume the proposed catalog exists.

**Survey:** mobile markup, inspection apps, facility management, BIM/CAD views, object segmentation, photorealistic image edits, manufacturer catalogs, review/approval flows and cross-industry annotation patterns. Inspect original user criticisms and exceptional cases rather than marketing screenshots.

**Inventory:** Android Photo Picker/SAF, URI grants, drawing overlay/undo libraries, metadata and image caching, manufacturer image licenses, AYA integration, existing related project code, automated test devices and cloud costs. Classify reuse/adapt/build, dependencies and trade-offs.

**Map:** photo version, target annotation, equipment identity, catalog reference angle, instruction, protected region, handoff, generated result and disclosure. Audit cancellation, obscured items, wrong perspective, two similar boilers, missing source grants and re-edit of a saved job.

**Decisions:** annotation model, storage lifetime, model-reference binding, assistant-generated region masks, version comparison and default/offline behavior. Surface grounded optional choices; do not force speculative decisions.

**Readiness:** independently assess local photo annotation, AYA outbound share and photorealistic composition. The first might proceed before the last is technically demonstrated. The image remains a conceptual illustration unless engineering evidence supports stronger claims.
