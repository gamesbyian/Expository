# Extract a complete, evidence-backed human choice landscape

**Trigger:** the user asks "what choices can I make?" or comparative research reveals product alternatives where human values matter. **Exclude:** a routine fix, decisions settled without new contrary evidence, or a purely technical choice established by hard constraints. **Inputs:** fresh decisions and source/behavior comparison, feature and user-journey inventory, actual project authority. **Output:** optional choice set with source evidence and stable IDs; no compelled form.

## H1. Build the candidate dimensions

From each distinct user job, contested control behavior, default/override, privacy or cost tradeoff, and mature competitor alternative, derive one question of the form "Should this user control or outcome behave as A, B or a supported alternative?". Include groups with opposite preferences under different contexts. Keep factual platform constraints out of preference polling.

## H2. Cross-check candidate coverage

Create a feature × control/outcome × user-context matrix. Reverse search from each important user journey and competitor capability to a possible choice. Mark dimensions already decided, agent-owned, needed for authority, optional and reconsideration-worthy. Deduplicate semantically identical questions while preserving independently different state/authorization consequences.

## H3. Qualify each alternative

For each choice ID record source/implementation/version, direct user report if any, actual cost or implementation constraint, affected actors, confidence basis, dependencies, existing owner decision, recommended default and observation that would change recommendation. A proposed novel alternative must be labelled speculative. Do not infer prevalence or invent 25 supported options when the evidence supports six.

## H4. Decide whether to show it

Needed now if distinct answers block an authorized implementation or require user approval. Upcoming if it affects future architecture but a reversible independent slice can proceed. Optional if experience preferences could matter but are not prerequisites. Reconsider only with material new evidence. No user leverage means agent-owned/informational; skip asking.

## H5. Render and preserve answers

Use a conversational question for one important unknown, optional grouped cards for many independent choices, staged presentation for dependencies, and comparison visuals where actual evidence exists. Support free-text correction and skip/defer/partial answers. Bind stable IDs, preserve raw response and interpret its speech act before proposing spec changes. Silence is neither approval nor rejection.

## H6. Reconcile with constraints and stop

Trace answered choice IDs back to evidence and forward to requirements, design and acceptance, updating project authority only with permitted writes. Leave unanswered options unchanged. If a correction challenges the evidence premise, reopen only the relevant source/model inquiry, not every settled decision.

**Oracle:** sample one choice and verify it truly changes a legitimate action and has original supporting evidence; reverse-trace one important user journey to ensure a relevant decision was not silently omitted. **Negative controls:** all decisions settled, source-light speculation masquerading as feedback, one owner correction treated as a checkbox answer, and a long compulsory survey replacing a requested research report.
