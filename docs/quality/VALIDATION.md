# Lean testing and CI policy

Expository has one routine PR validation check: Node's built-in test runner and static checks. It uses no package install, auth token, build server or external scripts. Root `index.html` is the shipped artifact.

- **Quick default:** `node --test tests/expository.test.cjs`, plus static JS syntax and verification that only expected workflow triggers exist. Run for PRs touching the app/tests/CI. Aim for a short, single Linux job.
- **Targeted browser:** `node tests/browser-smoke.cjs` when changing navigation, fetching, search, previews, modals or responsive UI. Uses synthetic public GitHub fixtures and local headless Chrome; neither live private data nor a production acceptance certificate.
- **Optional visual review:** Actions → *Expository Visual Review* → Run workflow on chosen branch/commit, capture viewport screenshot evidence and offline gallery. Never add it as a required check for unrelated changes. Keep captures synthetic and provenance labeled.
- **Manual physical inspection:** actual Pixel 6 Pro Chrome touch and layout, keyboard/screen reader checks, data-protection/network traces. Record owner observations separately. Even checked screenshot atlases do not substitute for handset/human acceptance.

One change should receive the cheapest decisive tests. View significant visual diffs directly. Do not invent pass/fail art thresholds from fixture PNG hashes; use hashes for provenance and visual regression assistance. CI cannot approve visual style by itself. Missing/queued/skipped evidence is **not** a pass. On failure, read first failed step and exact source SHA before retrying.

An additional opt-in **Expository Pages Surface Audit** checks the public URL against the exact local `index.html` SHA-256 and probes known public development paths with HEAD requests. Publicly served source/docs are not private secrets merely because they are also hosted by Pages. The audit is informational about path exposure but fails on unreachable or byte-mismatched app HTML; it does not publish, reconfigure Pages, or use credentials.

Pages deploys root `index.html` from public main. The former private publisher's `.expository-managed` marker must remain absent; the quick PR check prevents accidentally re-enabling stale overwrite. No CI token injection or private source sync. Public fixture screenshots may exist in 7-day artifacts but not silently in the live site.

## Private GitHub API reliability regression

API failures must not render raw GitHub error bodies, access tokens, or repository response content. Distinguish permission/auth failures from 403/429 rate limits, honoring `Retry-After`, `X-RateLimit-Remaining` and `X-RateLimit-Reset` without automatic retries. The cooldown is scoped to the active browser credential session, even when switching repos, and resets on explicit credential clearing. Repo switches and disconnects must abort pending fetches; async results must not overwrite the next repo. Public repository deep links are shareable; private file/path links must not be stored in the Expository fragment/history. Private Share copies a GitHub URL instead. These are checked by pure Node tests plus targeted Chrome fixture assertions, not yet a live token/device acceptance test.

## CI engineering standard and evidence

The [normative engineering standard](../CI-ENGINEERING-STANDARD.md) governs dispatch necessity, transitive change selection, reusable computation, failure diagnostics, least privilege and measurement. Expository Transfer has separate native verification gates. One owner-comment dispatcher delegates to approved manual/PR workflows; routine PR checks never contact live external providers or use owner credentials. `scripts/ci-selection.cjs` conservatively classifies renamed, shared/native and unknown changes. `scripts/ci-failure-digest.cjs` produces bounded redacted failure evidence. The tests guarding these contracts run in the fast Node suite.

External Actions are fixed to commit hashes, with original major versions recorded alongside the SHA in workflow YAML. Bump them only with exact-source verification and applicable CI evidence. See [Action pin register](CI-ACTION-PINS-2026-10-31.md), [dispatch evidence](CI-DISPATCH-EVIDENCE-2026-10-31.md), and [failure evidence](CI-FAILURE-INTELLIGENCE.md).

## Native PR and merge-queue selection (issue #366)

The native validation workflow **must receive every pull request**, including docs-only changes and files renamed *out of* `android-transfer/`. It runs a single inexpensive integrity selector on the trusted PR **base commit**, reads the complete paginated change inventory with rename origins, and verifies exact event head SHA both before and after classification. A changed head or API error makes the selection job fail. GitHub's 3,000-file listing cap, count mismatch or incomplete inventory triggers **both** native lanes as a conservative fallback. The JVM and Android compile/lint jobs depend on this selector and retain stable check names. They always run a tiny guard that **fails the required check context** if selection fails, is skipped, or returns malformed outputs. When a suite is inapplicable they explicitly report that no tests executed and skip all checkout, Gradle and SDK steps. This intentionally costs two small runner startups for docs-only PRs to preserve protection semantics even if branch rules have not yet been updated to require the new selector check. `merge_group` runs both native lanes and the web suite against the combined SHA. Owner-authorized manual jobs retain their independent events and reviewed-main trust boundaries.

Because a native workflow now creates a lightweight selection run for every PR, **top-level PR workflow counts may rise for web/docs-only changes**. That small dispatch is necessary to avoid pre-dispatch false negatives; it must not download SDKs or start Gradle on unrelated changes. Preserve check IDs `planner` and `android-pr-compile`; the new `Native change-selection integrity` check is decisive for metadata correctness. Review branch-protection contexts before removing any job. See [dispatch history](CI-DISPATCH-EVIDENCE-2026-10-31.md) and offline regression tests.
