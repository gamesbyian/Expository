# Universal locations: Android document providers, Google Drive and GitHub

**Product decision: 2026-10-27.** Binding future native-app scope, **not shipped functionality**. Owner requests that Google Drive folders and GitHub repositories behave as independently selectable locations in Expository Transfer's default single-location browser and optional dual-location workspace. Existing read-only GitHub Pages Expository remains separate and read-only. This document supplements [current product contract](CURRENT-CONTRACT.md), [Google Drive/Docs destination contract](GOOGLE-DRIVE-INTEGRATION.md), [workspace](WORKSPACE-AND-BULK-RENAME.md), [hardened plan](HARDENED-IMPLEMENTATION-PLAN.md), [release ledger](RELEASE-READINESS.md) and [native queue](../../android-transfer/WORK-QUEUE.md); their existing beta promises and safety invariants remain intact.

## User-facing contract

A location picker lists Device / Android document provider / saved FTP, FTPS or SFTP connection / Google Drive account / GitHub repository as capabilities become available. Either pane can choose independently, including different accounts, servers, or paths in one provider. The conventional single-location browser remains the default permanent full-featured mode; dual layout may collapse into A/B tabs at narrow widths, preserving pane identity and navigation. No feature requires keeping both panes visible.

Browse folders recursively with progressive pagination, breadcrumbs, previews, selection, search/filter and sorting according to truthful provider metadata. User can copy files or whole folders between any two authorized locations; dragging between panes **proposes Copy** and opens the same immutable preflight/confirmation as explicit Copy-to. Move requires separate explicit selection and destination content verification **before separately approved source deletion**. Add New folder, Rename and Delete only when a location reports and passes live capability, permissions and fresh membership/identity checks. Display provider-specific limitations instead of false universal promises. Keep progress, cancellations, recoverable partial jobs and receipts in the existing engine. Never silently convert native Docs/Sheets/Slides to plain files.

## Unified abstraction, not interchangeable filesystem assumptions

Introduce a provider-neutral `LocationRef` (provider kind, opaque account/authority ID, root scope, current container identity, credential/grant generation, optional branch + revision), `ItemRef` (opaque stable identity **when available**, path/name, object kind, version/ETag/last-modified if authoritative), `LocationCapabilities` (list/read/create/write/delete/rename/server-side move/recursive folder/seek/resume/version support), and `LocationAdapter` (paged list, metadata, stream read, destination creation/write, post-write reconciliation; conditional mutation operations).

No location adapter may fabricate stable identity, atomicity, complete listings, seek support, permanent permission, server-side copy or successful completion. Names/paths are display values, never authorization substitutes. Separately distinguish writable existing destination folder, per-file Save As, app-owned folder, and external Sharesheet handoff. Reuse the immutable planner, side-effect executor, journal, uncertainty stop/reconciliation, bounded streaming and proof tiers. No opaque credentials, bearer tokens, GitHub auth, private listing, or file bytes in drag payloads, logs or published artifacts.

Cross-provider transfers normally stream **through the Android device** in bounded chunks, using staged data only when required and safe; never imply provider-to-provider server-side transfer. Require fresh grants, collision checks, destination child identity, approved destination and per-file results. Streams may be nonseekable; resumability is provider-specific. Moves across authorities are verified copy plus separately authorized deletion, with no delete after ambiguous destination results. Folders preserve hierarchy including empty folders when destination can represent them; Git cannot represent empty folders without explicit alternative. Avoid unbounded tree scans; show counts and incomplete coverage transparently.

## Android Storage Access Framework (SAF): first generic provider

Use Android `ACTION_OPEN_DOCUMENT_TREE` for user-selected folders when provider allows; fall back to `ACTION_OPEN_DOCUMENT`/`ACTION_CREATE_DOCUMENT` for file-scoped operations. The familiar Android DocumentsUI picker grants access to the returned URI, **not a guarantee of all Google Drive, full account root, arbitrary shared drives, or indefinite access**. Take persistable URI grants only when offered and revalidate on every session/operation. Support cloud-backed document providers, not just Drive, without requiring per-provider OAuth for scoped access. Respect `DocumentsContract` flags and actual mutation/relisting behavior; revocation, offline, delayed indexing, duplicate/changed IDs and provider redirects must stop unsafe writes.

A user-selected Drive tree, if available and writable, is a first-class browseable location with Device/FTP/SFTP/GitHub counterparts; inability to select an entire Drive root must not be disguised as permission failure. Prove the actual installed Google Drive provider behavior at E4 before claiming support.

## Dedicated Google Drive API adapter: second route, not replacement

Where SAF cannot expose required folder/account navigation or write semantics, provide Google account authorization via supported OAuth system flow and Google Drive API, separately from Android document grants. Least privilege first: `drive.file` plus a genuinely supported picker-selected/app-created destination; validate actual authorization of the selected parent before promising copy or browse. If full-account browse/search, Shared Drives or third-party folder write needs broader scopes, gate that behind explicit consent, security/compliance review and product decision; do not silently escalate to restricted scopes. Do not label the existing ChatGPT connected Drive integration as app authorization.

Support paging/queries, file IDs, parent IDs, shortcut semantics, revisions, Google Workspace native types, quota and rate limits, resumable upload reconciliation, account switching/revocation and conflict policies. Export Docs/Sheets/Slides with explicit user-selected format and conversion warning, recording conversion proof separately from byte-equal copies. Preserve the existing destination-only P0 requirement even while full browseable Drive accounts are phased in.

## GitHub repository location adapter

Offer anonymous, rate-limit-aware **read-only** browsing for public repositories and secure account authorization for private repositories or mutations. Treat Owner/organization → repository → branch/tag/commit → directory as navigation levels; fixed commits and protected/read-only branches must be visibly immutable. Allow separate repo/branch choices per pane. Never reuse the web Pages explorer's token or violate its read-only contract.

For changes, require a scoped GitHub authorization with secret storage in the native device-vault design, permissions explained and revocable. Prefer a new branch, reviewed coherent multi-file commit and optional pull request; direct branch commits require explicit mode and branch protection checks. Represent file uploads, rename/moves and folder copies as a proposed Git tree diff reviewed before mutation, not an FTP-like immediate write. Record base commit SHA and refuse stale approvals when HEAD changes; reconcile ambiguous commits by commit/tree identity to avoid duplicates. Git doesn't store empty directories; show an explicit choice to skip/represent them, never invent folder creation. Submodules, symlinks, LFS pointer/content mismatch, binaries, GitHub API Contents limits, large Trees, API quotas and GitHub's changing write restrictions must be handled/declined explicitly, not falsely claimed supported. Favor Git Data Trees/Blobs for coherent batches when appropriate; no automatic conversion of repository source into executed content. Avoid creating one commit per file in folder transfers.

## Current E1-only foundation (2026-10-27)

Merged [#195](https://github.com/gamesbyian/Expository/pull/195) introduces a **pure Kotlin** `LocationListingAdapter` contract and bounded `PagedLocationIndex`: 200 records per page, 2,000 maximum, explicit snapshot and continuation identity, duplicate-name/child-ID rejection, grant/revision drift failure, and no destination collision witness until the complete listing is proven. `GITHUB_REPOSITORY` is recognized only as a planner location kind; generic GitHub destination Copy and Move are blocked until an explicitly reviewed Git tree commit flow exists. E1 `locationScenarios` exercise synthetic SAF, SFTP, Drive and GitHub pairings and failure cases. The Android application has **no live paginated Drive API/GitHub repository adapter, new account authorization, new location picker or real device cross-provider byte transfers** from this change. Existing guarded device/remote functionality remains as described in the native queue.

## Delivery sequence and acceptance

1. **Foundation**: capability-driven types/adapters, fake provider matrices and default Single + optional Dual picker. Preserve current Local/SFTP/FTPS paths while migrating them without regression.
2. **SAF cloud provider locations**: tree browse, persisted/revoked grants, paging, copy Device ↔ provider and SFTP/FTPS ↔ provider, recursive folder copy, A/B + drag equivalence. Record E2 disposable DocumentsProvider and E4 actual Google Drive separately.
3. **Dedicated Drive API**: only where needed for verifiable destination and extended account-wide browsing; auth and scope/security review precede claims.
4. **GitHub read-only**: public repo/branch tree browse, paging/caching and downloads with anonymous rate-limits. Then private auth and safe writes via branch/diff/commit/PR.
5. **Generalized cross-provider move and recovery**: exhaustive pairwise permission/collision/revocation, uncertain commit, offline, large folder and conversion cases; never weaken copy-first proof.

Acceptance examples: Drive-pane to SFTP-pane drag a nested folder and check unchanged source + verified bytes, reverse direction, GitHub-public to SAF Copy, GitHub authorized reviewed changes via new branch, GitHub ↔ Drive with correct native Docs export options, two distinct cloud accounts, same-account two panes, switched/revoked grants, network loss after upload response, changed Git HEAD during preflight, and 2,000+ child bound. Run E1 planner invariants, E2 emulator DocumentsProvider, E3 controlled remotes, **E4 real Google Drive/GitHub credentials and device** and E5 release tests independently. No fake providers or compile-only builds count as actual Google Drive or GitHub interoperability.
