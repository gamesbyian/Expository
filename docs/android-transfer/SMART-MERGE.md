# Smart Merge: arbitrary multi-source folder consolidation

**Status (2026-11-02):** binding product/UX requirement. **M1 basket and a bounded, read-only M2 preview foundation exist**, but the user-facing merge feature, source-basket UI, live provider enumeration, complete M2, M3–M4 and provider/device E2–E5 remain **unimplemented/unaccepted**. Native Expository Transfer only. Complements [CURRENT-CONTRACT](CURRENT-CONTRACT.md), [WORKSPACE-AND-BULK-RENAME](WORKSPACE-AND-BULK-RENAME.md), [OPERATION-STATE-UX](OPERATION-STATE-UX.md) and [EXECUTION-DEPENDENCIES](EXECUTION-DEPENDENCIES.md). Existing no-overwrite, permission, identity, journaling and evidence rules take precedence.

**M1 shipped slice:** [PR #389](https://github.com/gamesbyian/Expository/pull/389), merged `96439eb`, provides a pure Kotlin, RAM-only immutable `SmartMergeBasket` and scoped `SmartMergeFolder` with 2/20/64 E1 tests, native [#41361946895](https://github.com/gamesbyian/Expository/actions/runs/41361946895) and web [#41361946858](https://github.com/gamesbyian/Expository/actions/runs/41361946858) passing. It collects across Single/A/B, SAF and proven remote identities; refuses known overlapping/duplicate selections, ungranted SAF and unproven/expired READ state; supports remove/reorder/clear. The 64-entry implementation bound is provisional. No UI, provider reobservation, executable plan, destination selection, copy, delete or persisted access is introduced. Finish M1 wiring and source refresh before M2.

**M2 code-only foundation:** [PR #394](https://github.com/gamesbyian/Expository/pull/394) introduces a non-executable `SmartMergePreviewPlanner` fed by the ordered M1 basket, independently complete `RecursiveFolderManifest` observations and a verified destination-parent `PagedLocationIndex`. It binds the digest to source versions/grants/proof IDs/ordering, destination scope/proofs/listing, selected structure and proposed paths. Default is to retain both same-named files and directories with deterministic numbered suffixes; optional matching-directory coalescing *only* shares directory path in the preview and still preserves both conflicting files. It blocks unknown destination case policy, unreadable/expired/partial trees, missing create authority, nested destination, root-name collision and >10,000 preview entries. It is **not** a creation or write authorization, a UI, a paged real-provider tree reader, a content deduplication proof or an accepted operation. Android actual picker/bytes acceptance and all execution remain later phases. Source-basket UI M1 wiring must still precede usable M2 UX.

**M1 fresh-source inspection follow-on:** [PR #395](https://github.com/gamesbyian/Expository/pull/395) merged as `85757a69` after [native #41374717700](https://github.com/gamesbyian/Expository/actions/runs/41374717700) and [web #41374717795](https://github.com/gamesbyian/Expository/actions/runs/41374717795) success. A basket can be preserved across pane changes without implying that its old READ grant or remote session is still usable. A pure `SmartMergeFolder.inspectFresh` / `SmartMergeBasket.inspectFresh` check compares exact newly observed opaque source identity, provider root, grant/session/storage namespace, name, version, listing revision and capability proof. It reports current, missing, untrusted/expired, different object, changed authority or changed contents without modifying or silently reauthorizing the basket. This is a **non-executable E1 diagnostic model only**; provider re-query UI and user reapproval are still missing. **Never** use a current status as permission to execute a merge without fresh complete inventory, target preflight, journal and explicit confirmation.

## Product contract
- Merge **N >= 2** selected source folders in **one coherent operation**. No artificial two-source limit, including selections collected across both panes, arbitrary navigation sessions, different local SAF authorities/grants, FTP/FTPS/SFTP profiles, and Google Drive when its real authorized adapter is available. Supported destination is independently chosen and may belong to none of the sources.
- Single-pane users have the same multi-source feature. Dual-pane is a convenient source discovery surface, not a structural source limit. Persist a scoped **merge basket** across pane navigation and layout changes; display provider/account identity, path, source count, unknown access, and per-source remove/reorder. No secret/path payload in external drag/clipboard.
- Three structural plans: **combine contents** (default), **recursively merge matching directory paths**, **propose consolidation/flatten redundant wrappers** (opt-in). Include empty folders; preserve hierarchy and names unless a user-reviewed rule changes them. Detect source overlap, parent/child duplication, destination nested within source, symlinks, cycles and unsafe provider aliases; block or explicitly resolve rather than double-ingesting.
- Destination naming is suggested, editable, and validated against its provider: shared meaningful stem, date/number range, version patterns, or neutral name on low confidence. Never infer content identity or delete based on names. Per-file collision suggestions may use original source label, date or sequence with deterministic stable tie-breaks. Preserve extension by default; Unicode normalization/case folding obey actual destination rules.
- Distinguish **same path/name**, **same size/metadata**, **verified same bytes** and **different bytes**. Hash equality requires full successful reads (or equally strong trusted hashes); missing/unreadable material remains unresolved. Default collision policy: preserve both with predictable disambiguation. Offer skip, per-item review, and exact-hash deduplicate after verification. **No automatic overwrite or source deletion**.
- Unified plan before any write: frozen source authority, immutable URI/remote identity, listing revisions, permissions/trust, target identity, conflict graph, explicit policies, total known/unknown size, transfer route (handset relay by default across remotes), network/metered/device-storage cost warnings, and stable review digest. Recheck just before writes and per item; stale source/target/capability invalidates or pauses plan for user reapproval. No FTP FXP assumption.
- Perform non-destructive destination creation/copies first; journal per-source/per-entry attempts and immutable receipts (queued, attempted, acknowledged, independently inspected, byte/hash-verified, uncertain, skipped, failed). Stage where supported; handle lack of atomic rename honestly. Abort/pause safely on cancellation, crash, app death, auth expiry, revocation, changes or low space. Never blindly retry uncertain creates or overwrite. Clean-up originals is a **separate explicitly approved** step after verified destination, with an individual deletion eligibility check. Undo only where provable.
- Represent physical provider limits honestly: unavailable Google Drive/other adapters must appear disabled with explanation, not pretend universal interoperability; read-only sources may merge into a writable destination, and any destination may reject a proposed name/path. Browsing enumeration is bounded/paged but must not quietly produce a partial *complete* merge; report truncated/unknown inventory and block unsafe execution until resolved.

## UX contract
1. Multi-select folders → **Merge folders**; or long-press **Add to merge** from any pane/location. Both actions accumulate in the same basket. Drag onto a folder offers a **Merge…** action separately from default Copy; drag alone never mutates.
2. Persistent compact basket chip “Merge · N sources”, with source list and provider badges, accessible Remove/Clear and selection count. Switching profile, pane, A/B tab or orientation must not discard an active basket; invalid grants must show a recoverable state.
3. Choose **destination** via the same trusted picker/navigation capabilities as Copy; source identities and chosen target shown together. Optional new folder and editable suggested name.
4. Choose structure (combine / recursive / smart flatten opt-in), suggested naming alternatives, preserve source labels, duplicate detection, collision policy (keep both default, review, skip), optional source cleanup (**off** by default).
5. Display **dry-run preview** before confirmation: proposed tree, old→new mapping, per-source count, all collisions, identical-content proof state, insufficient data, projected cost, and exact actions. Virtualize large results; filter conflicts/warnings; changes to any rule replan deterministically. One sticky **Review and merge** consent button and a non-gesture equivalent.
6. During execution show N-source progress, per-item provenance, verified vs merely acknowledged, pause/stop and uncertain receipts. Post-operation summary separates successful copies, unresolved and untouched originals. Never call partially completed operations “merged”.
7. Portrait 320–412dp and 200% font: bottom sheet/fullscreen progressive flow, 48dp targets, safe insets, no horizontal overflow; landscape/tablet may show basket alongside panes. TalkBack/keyboard fully supports adding sources and reviewing every conflict; no reliance on drag, color or gestures. Retain focus and selection on rotation/recovery.

### Example preview
Sources: `Local/DCIM/2024`, `SFTP/Backups/2025`, `Drive/Shared/Family`, `FTP/Archive`. Destination: `SAF/Documents/Family Photo Archive`. `IMG_001.jpg` in two sources with differing verified bytes becomes `2024 - IMG_001.jpg` and `2025 - IMG_001.jpg`; exact verified duplicates may be represented once **only if approved policy says so**. Unknown metadata or failed hash means keep both/review, never silently coalesce.

## Architecture & phased work
- **M1 (dependencies):** provider-neutral `SourceFolderRef[]`/basket, snapshot and identity validation across sessions; contract tests for nested/overlapping sources, revoked grants, disconnected remote, changing listings and independent destination; reuse existing command-owner/operation journal. Implement no new parallel dispatcher.
- **M2:** deterministic immutable N-source merge planner, recursive bounded enumeration with honest coverage, path/conflict graph, naming suggestions, stable digest and virtual preview; pure Kotlin property/fixture tests including case/Unicode, 10k-item previews and 2/3/20 sources.
- **M3:** execute non-destructive local SAF→SAF and qualified SFTP/FTPS/FTP routes through the shared Copy engine, journal + exact readback, cancellation and crash/reconciliation tests. Extend into remote→remote relay and Drive only after corresponding provider contracts are proven. No early source deletion.
- **M4:** verified deduplication, advanced naming/date/sequence patterns, optional smart flatten, explicit post-verification cleanup, independently reviewable recovery/undo where possible; no AI or content classifier needed for baseline.
- **Evidence:** E1 planner and fault injection; E2 installed API35 real OS-picked 3+ folders from two independent providers, then cross-pane/rotation/TalkBack; E3 controlled protocol cross-source/cross-server exact byte readback; E4 authorized real external SAF/remote/Drive interoperability; E5 physical handset/accessibility beta. Never conflate mocks with E4/E5.

## Acceptance scenarios
- 2, 3, 20 sources across changing panes and locations; source basket survives layout/navigation and never leaks credentials.
- Identical and nonidentical same-name files, Unicode/case collisions, deep matching folders, empty directories, same source twice, ancestor+child selection, destination inside source.
- Partial/inaccessible listing, changing content between preview/apply, revoked grant, expired remote login, disconnect, low space, cancellation before/after remote acknowledgement, restart, re-pick and uncertain create: zero silent overwrite, duplicate mutation or false completion.
- 320×700 and 412×892, 200% font, keyboard/TalkBack, gesture-free operation; large previews remain responsive.
- Successful readback from all sources into a destination belonging to another provider, originals retained by default; explicit cleanup never precedes verified output.
