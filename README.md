# Expository

The **Sizes** view turns the already loaded Git blob index into an interactive file-size treemap with folder drill-down and an accessible list. Truncated tree indexes are marked as partial; no extra file scan is performed.

### Explore the story of your repository.

A mobile-first, dark-first visual explorer for GitHub repositories, with just enough rainbow to make a directory listing feel alive.

**[Open Expository](https://gamesbyian.github.io/Expository/)**

Expository browses **public repositories without login** and can browse selected **private repositories** using a fine-grained GitHub personal access token with **Contents: Read-only** access. Tokens stay in the browser tab's memory: they are not saved to local storage, embedded in links, or sent to an Expository server. For public repositories Expository keeps shareable browse links in the address bar; for **private** repositories it clears repo/path fragments, including incoming links that fail authentication, and the share control copies a standard GitHub URL instead. Private browsing still requires the visitor's own GitHub authorization. Use only your own trusted deployment when supplying a token. A user with a private-repo link still needs their own GitHub access.

## What you can do

- Explore branches and collapsible nested folders; jump back to the last eight successfully visited folders from the repository menu. Recent paths exist only in this tab, never local storage, and disappear on repository/branch switch or disconnect.
- Search paths across a repository; browse every image across the entire repository or galleries of images and other files in any folder and its descendants
- Switch between gallery thumbnails and compact file lists
- Browse up to 100 branches on demand from the repository menu, or enter any branch manually; private branch names stay in tab memory
- Sort by name, size, extension, full path or **last changed (known dates)**. Date sorting consults GitHub's per-file commit history **only after clicking Look up dates**, for at most 12 visible files per action with three concurrent requests and 240 per tab session. Dated files show actual commit-history dates, while unqueried/unknown dates sort last in either direction. Filter by file category and exact file extensions (such as png, svg, html), including HTML and previewable documents, optionally group gallery rows by containing folder, and adjust thumbnail density using collapsible phone filters
- Run bounded, opt-in full-text scans with matching-line snippets
- Inspect ZIP archives as nested, inert virtual folders; preview members, save individual extracted members, choose up to 12 entries for a device-folder extraction or Android native file-sharing batch, and extract a whole archive into a user-picked device directory where directory-write access is supported. The always-visible **ZIPs +** toggle includes eligible archived members in recursive thumbnails, with a lazy three-worker thumbnail queue and bounded paging. ZIP inspection is limited to 24 MB archives, 16 MB/member and 128 MB total declared uncompressed data; no ZIP64/encrypted/symlink members; gallery scans at most 12 archives with a 64 MB aggregate compressed-byte budget and 1,000 members per archive. Sharing batches are further limited to 12 MB and must have distinct filenames.
- Publish a verified subset or eligible entire ZIP into a **new GitHub branch** through a separate user-authorized companion, with preflight collision review and no write credentials in the main viewer
- Read source with line numbers and lightweight syntax colours; copy or download originals
- Find text across the current source section, cycle matching lines and jump directly to loaded lines, including deep lines reached from repository-wide content search. Source rendering stays limited to 500 DOM lines at a time; already downloaded text larger than 500,000 characters has Earlier/Later controls and a whole-file Go to Line shortcut across successive bounded sections, with original line numbers and explicit mid-line continuation. No extra GitHub read is needed to change section; the existing 20 MB file-response ceiling still applies. Rendered Markdown and SVG image previews can switch to inert raw source, and content-search hits switch to raw source when line navigation requires it. The optional **heuristic** symbol outline jumps to likely functions, classes and types in JS/TS, Python, Rust, Go, Java or Kotlin within the current section. Outlines are not full language parsing.
- Star public repositories for quick switching, without storing private repository names
- Preview SVGs, photos, plain/safe Markdown, source files, PDFs, and supported media; galleries show safe static text thumbnails for small HTML/Markdown/data documents, with no execution of repository HTML or scripts
- Pin two images for side-by-side comparison, touch-friendly reveal, or a bounded local pixel-difference heatmap
- Select up to 12 images across repository folders, inspect a contact sheet, and save a PNG locally without uploading private art. The same loaded images can be viewed as a **browser-local slideshow** with Previous/Next, Play/Pause, keyboard arrows, 3/5/10-second intervals and return to sheet. Playback starts only on Play, makes no new GitHub requests, and stops on modal close or private-session cleanup; actual phone/assistive-technology acceptance remains outstanding.
- Zoom images from 1× to 4× with two-finger pinch and drag-to-pan gestures, or use keyboard-accessible zoom controls; native page scrolling stays available at fitted 1×. Rotate raster and SVG previews clockwise in 90° steps, with geometry fitted to the stage; rotation never modifies the downloaded original. Where the browser supports the Fullscreen API, the image viewer has a fullscreen/exit control, with Escape exiting fullscreen without abandoning the preview; unsupported/refused fullscreen is clearly surfaced.
- Inspect the recent Git history of an individual file
- Expand JSON as a safe tree or switch to raw source
- Follow safe relative Markdown links within repositories and view CSV/TSV as bounded tables
- Enter Story Mode for dated GitHub commits, releases, genuinely merged PR milestones and undated tags. Load older commits explicitly, up to four pages (200 commits). PR discovery starts with the 20 most recently updated closed PRs, and you can explicitly load up to 3 older pages (80 closed PRs total). Only genuinely merged PRs enter the dated story, and even 80 closed PRs may omit older merges.
- Jump from any recursive gallery tile or open preview to its containing folder; copy deep links to folders and previews
- Switch dark/light appearance, and clear private browsing credentials explicitly

Story Mode uses real GitHub evidence, displays the sample size, and makes no claim to reconstruct missing history. The [feature roadmap](FEATURE-ROADMAP.md) distinguishes shipped capabilities from remaining planned work.

The standard Expository viewer remains **read-only**. ZIP publishing is available only through a **separate, explicitly authorized** companion page opened by **Publish ZIP to GitHub…** in the archive viewer. The browser passes already verified files through a one-time memory-only handoff; the companion requires a separate fine-grained GitHub token with Contents: Read and Write, performs a destination/collision review, and creates **a new branch**, never modifying your existing branch. Publishing is limited to 100 files, 32 MB total and 16 MB per file; live token and physical-browser acceptance are still outstanding. Folder extraction needs a supporting browser and user-granted destination; on supporting devices, **Share selected…** passes previously verified files to the OS share picker. Unsupported browsers can still download members individually. Device files already present are skipped rather than deliberately overwritten. Folder export is sequential and cancellable between files; it is not an atomic operation. The ZIP gallery uses local archive reads, never an external conversion service.

The main browser explorer is **read-only**, uses direct requests to the GitHub API, and has no advertising, analytics, server-side session store, or dependency-loaded remote scripts. Its browser Content Security Policy restricts outgoing fetches to the GitHub API and forbids remote scripts, workers, objects, and external media origins. Inline app code/style and browser-local blob previews are allowed to preserve the standalone-file architecture. This is an additional defense, not a substitute for the inert DOM renderer and private-token checks. GitHub API rate limits and tree-index truncation may limit results on large repositories. When GitHub's 1,000-entry directory limit is reached and a complete Git tree index is available, Expository supplements the folder from that existing index, without additional API requests. If the recursive Git tree is truncated or unavailable, Expository can instead try bounded nonrecursive Git tree reads for the currently opened capped folder (root plus up to eight directory levels), or use an exact tree SHA from a previously visited ancestor or a valid, bounded partial recursive index to recover deeper capped directories with at most eight direct tree requests. Same-path SHA changes and duplicate tree entries invalidate verified coverage. An uncached and unindexed very deep folder may still be incomplete. It labels incomplete responses and caps displayed recovery at 5,000 direct tree entries; it never treats a truncated result as complete. On a rate-limit response Expository uses GitHub's reset/Retry-After headers where available, shows a retry time, and refrains from making further requests during the cooldown. Requests started in an older repository/session are aborted when switching or disconnecting. It is not a replacement for GitHub's editor. The optional [ZIP publisher](zip-publisher.html) is a separate, higher-permission operation, never needed for viewing.

Per-file modification dates are not part of GitHub's recursive tree index. The opt-in date sort uses **attested commit-history timestamps** for a bounded sample of visible files, with explicit unknown coverage. It does not reconstruct an exhaustive per-file timeline, and a moving branch can change while data is being fetched. GitHub file responses are also limited by their **actual streamed bytes**, not solely by advisory GitHub metadata: regular preview 20 MB, ZIP archives 24 MiB, image thumbnails/contact sheets 8 MB, document thumbnails 160 kB, and content scans 128 KiB. Huge repositories and truncated tree indices can yield incomplete recursive results; Expository labels that limitation.\n\nFor the feature plan and current development stages, see the [weighted feature roadmap](FEATURE-ROADMAP.md). Not every planned item is implemented.

## Expository family: Android Transfer development

A **separate, relocatable native Android project** lives under [`android-transfer/`](android-transfer/) (initial foundation [PR #32](https://github.com/gamesbyian/Expository/pull/32)). The FTP/FTPS/SFTP transfer client is a **developer preview, not beta-ready**. It now includes scoped Android real system-picker Local→Local Copy with API 35 E2 proof, controlled secure SFTP/FTPS sessions, SFTP file Save As/exclusive upload, direct New Folder/one-file Move, private attempt journals and safe external Open/Share handoffs. The app has a **default Single workspace** and an **optional two-pane Dual workspace** with independently selected Local/Local, Local/Remote and Remote/Remote locations, although Single/remote action parity and the full six-route matrix are unfinished. Genuine two-provider, system-picked Single and Dual **recursive Local SAF Copy** passed scoped Android API35 E2 tests ([#399](https://github.com/gamesbyian/Expository/pull/399), [#401](https://github.com/gamesbyian/Expository/pull/401)), including byte readback, unchanged originals, destination refresh and clean Dual Activity teardown. Other SFTP/FTPS operations remain route-specific; insecure plain FTP is separately consented **read-only browsing**, never a plaintext transfer fallback. The SFTP bulk renamer is still preview-only, and remote recursive route parity, actionable restart recovery, Google Drive/Docs verified destination or conversion, physical-device E4 and signed release E5 remain unaccepted. This does **not** expand the read-only GitHub explorer's permissions or modify its deployed Pages app. The first requirements are native Android **Save to device** / **Upload files or folders** using system interfaces, optional Device/Device, Device/Server and Server/Server split panes with drag-and-drop and accessible copy controls, fast same-server **Move to… → New folder** and a compact preview-first **bulk renamer**.

## How this site is published

This public repository is now the **canonical application and development source**. The earlier `gamesbyian/general-purpose/tools/expository/` version is preservation/bootstrap history, not a second active development lane. The Pages deployment continues to use root `index.html` only. Public agent instructions, synthetic test fixtures and visual review scripts live beside it; no personal repository content or credentials are included.

The original `.expository-managed` marker has been removed deliberately: it prevents the archived guarded publisher in the old private source from overwriting current public development. `.nojekyll` disables Jekyll transformations.

For a byte-level release check, run the manual **Expository Pages Surface Audit** Action, or run `node scripts/pages-audit.cjs` with network access. It compares the deployed `index.html` with this checkout and reports whether a few already-public development paths are also served through Pages. The check does not change settings, download private content, or submit credentials. A public repository does not become private just because its development files are omitted from Pages.

For development work, start at [AGENTS.md](AGENTS.md) and [the live work queue](docs/WORK-QUEUE.md). For screenshot acceptance and a standalone offline atlas, see [visual review](review/README.md) and the manual **Expository Visual Review** Action. The [weighted roadmap](FEATURE-ROADMAP.md) is the strategic feature list; it is not evidence that every item is already implemented.

## Development and verification

The ordinary PR check runs `node --test tests/expository.test.cjs` plus lightweight script syntax checks. For meaningful interaction changes, run `node tests/browser-smoke.cjs` with Chrome installed. Visual reviews are **manually dispatched**, synthetic-data-only, and produce an offline HTML screenshot atlas with SHA/provenance receipts. A passing browser run does not imply Pixel 6 Pro handset approval or artistic acceptance.
